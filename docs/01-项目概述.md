## 1. 项目简介

**项目名称**: ETF 多资产动态配置策略系统

**项目定位**: 基于前后端分离架构的 ETF 量化回测与参数寻优平台，支持多资产动态配置、双策略并行执行、历史区间回测与可视化分析。

**当前状态**: 核心功能开发完成，支持完整回测流程与参数寻优

**技术架构**:

- 前端: Vue 3 + TypeScript + Vite + Element Plus + ECharts
- 后端: Node.js + Express + 极简 ORM 模型层
- 数据库: MySQL 8.0

## 4. 核心功能模块

### 4.1 已实现模块

#### ETF 资产管理与禁用风控

- ETF 标的添加、编辑、删除、历史断点自动填充行情同步。
- **初始配比融合面板**：将初始配比管理彻底合并嵌入 ETF 管理卡片。
- **一键启用/禁用物理风控**：勾选禁用的资产初始比例强配置归 0 并置灰；在策略配置页面**完全物理隐形隐藏这一列**；在后端回测启动第一时间执行**静默自清洗物理剥离**，实现绝对的安全隔离。

#### 策略配置与自解耦（乘数模型）

- **专属步长整倍数（乘数模型）**：策略 A/B 的偏离分配采用“倍数控制”（持久化仅存储相对于专属步长 $S_i$ 的整倍数乘数，如 `-1`、`+2` 等整数），实现**基础步长一改，整个策略全自动瞬间联动**的数据自解耦架构。
- **偏离加权零和守恒**：提供前端微调防呆校验，要求启用标的在每一档的 `(倍数 × 专属步长)` 加权偏离之和刚好为 `0%`（即占比完美配平归零），守恒总实际持仓恒等于 100%。

#### 历史回测与策略进化

- **回测引擎 2.0**：逐日推进的内存沙盒流动轴；首日建仓折算以及上市首日自动延迟补仓，杜绝穿越漏洞。
- **策略 A 的终极进化**：支持回撤加深下跌分档加仓；反弹时“多跨一档退档”锁定高配弹性；净值创历史新高（正收益）时一键填平复位。
- **策略 B 估值进攻防御**：计算滚动累计几何年化，偏离长期收益中枢时高估防御下调、低估进攻收集。
- **多策略决策融合**：双重信号在同日触发时自动依据 `strategyPriority` 优先级策略合并，避免摩擦损耗。

#### 终极三维网格参数寻优

- 支持遍历初始配比排列组合、再平衡偏离阈值、策略 A/B 开关组合等高维笛卡尔积参数网格寻优（共 504 组回测组合）。
- 寻优计算时开启 `isOptimization` 静默缓存技术，不写庞大明细，保证数据库绝对安全。
- 自动分析夏普比率、卡玛比率，输出“性价比之王”、“防暴跌之王”、“绝对收益之王”三大推荐卡，并一键生成 CSV 数据报表。

#### 数据可视化

- 组合净值走势曲线与沪深300基准收益率双曲线对比。
- **高阶行合并调仓流水表**：高频调仓流水按交易时刻将日期与账户总额跨行合并展示。
- 回撤幅度走势图与资产配置占比变动多标的堆叠面积图。

## 5. 系统架构

### 5.1 MVC 三层架构

系统采用严谨的 MVC 分层设计:

| 层级 | 目录 | 职责 |
| --- | --- | --- |
| 路由控制层 | `routes/` | HTTP 请求分发、参数校验、响应输出 |
| 模型层 | `models/` | 数据库读写、ORM 封装 |
| 服务层 | `services/` | 核心算法、策略引擎、爬虫 |

### 5.2 核心业务流程

```
启动回测参数 -> 锁定基准(510300)
  -> 读取历史行情 -> 首日建仓
  -> 逐日循环: 更新价格 -> 延迟补仓
  -> 策略A/B信号研判 -> 决策融合
  -> 日常再平衡 -> 推进下一日
  -> 循环结束 -> 计算量化指标 -> 存盘输出
```

### 5.3 数据库关系

系统共 7 张物理表，以 `etf_basic` 为核心关联 `etf_history`(历史行情)、`trade_records`(交易流水)、`backtest_results`(回测结果)，辅以 `global_config`(全局配置)、`strategy_a_config`(策略A配置)、`strategy_b_config`(策略B配置)。

## 7. 技术特点

### 7.1 极简 ORM

参考 ThinkPHP 风格的万能 ORM 基类 `BaseModel.js`，所有数据库读写通过统一模型基类完成，杜绝裸写 SQL 注入风险。

### 7.2 内存沙盒回测

回测引擎在内存沙盒中闭环运行，逐日推进，所有计算不依赖数据库事务，确保无"未来数据穿越"的学术漏洞。

### 7.3 防爆盘保护

海量参数寻优时通过 `isOptimization` 标记禁止写入大 JSON 字段，防止数据库爆盘。

### 7.4 决策融合引擎

多策略冲突时通过优先级机制合并决策，避免同一交易日多次调仓造成资产擦除与双重手续费。

### 7.5 统一规范

| 规范项 | 约定 |
| --- | --- |
| HTTP 方法 | GET 用于查询，POST 用于创建/执行，PUT 用于更新，DELETE 用于删除 |
| 参数命名 | API 请求统一使用 camelCase，数据库字段统一使用 snake_case |
| 响应格式 | 统一 JSON 格式：`{ success: boolean, data: any, message: string }` |
| 错误处理 | 路由层统一 try-catch 包裹，错误通过 `res.status(500).json({ success: false, message })` 返回 |
| 数据模型 | 所有数据库操作通过 BaseModel 完成，禁止裸写 SQL |

### 7.6 安全机制

- **SQL 注入防护**: 通过 BaseModel 参数绑定机制防注入
- **参数校验**: 前端使用 TypeScript 类型校验，后端在路由层进行必要参数校验
- **事务保护**: 配置批量更新使用数据库事务保证一致性
- **日志记录**: 日志记录: 关键操作(添加/删除 ETF、配置变更、回测执行)记录操作日志

- `feature/*` — 功能分支，如 `feature/backtest-optimization`

### 8.3 提交规范

```

docs(api): 更新API文档
refactor(model): 重构 BaseModel 查询方法
style(ui): 调整回测结果表格样式
```
