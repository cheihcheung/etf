## 1. 回测引擎核心流程

回测引擎位于 [backtest.js](file:///d:/trae/etf/server/src/services/backtest.js)，采用"时间流动轴"沙盒模型，在内存中闭环运行，逐日推进。

### 1.1 总体流程

```
启动回测参数 -> 智能锁定基准（优先查询数据库中包含'沪深300'名称的 ETF，默认兜底使用 '510300'）
  -> 执行【禁用资产静默自清洗】：剔除物理禁用的 ETF 并从参数中剔除其初始占比
  -> 加载全标的【专属加减比步长(step_ratio)映射表】
  -> 读取所有激活标的历史行情数据
  -> 回测首日: 执行初始建仓(每手100股向下取整)
  -> 逐日时间轴主循环:
     -> 更新每日最新收盘价并维护价格记忆
     -> 延迟补仓(针对首日未上市标的，于上市首日按初始占比买入)
     -> 策略A信号研判 (回撤加仓、跨级退档与新高复位)
     -> 策略B信号研判 (年化中枢偏离高低估乘数加减仓)
     -> 决策融合引擎(双信号同日触发时，按优先级合并一次性交易)
     -> 日常再平衡偏离度校验与对齐
     -> 推进到下一交易日
  -> 循环结束
  -> 计算全套量化指标(年化、波动率、最大回撤、夏普、卡玛比率等)
  -> 保存回测/寻优结果排行
```

### 1.2 首日建仓规则

- 读取各标的在回测首日的收盘价。
- 依据配置的 `initialRatios` 占比进行初始配资。
- 买入股数按 **100 股(一手)向下取整**，以保障实盘可行性：
  $$\text{shares} = \left\lfloor \frac{\text{totalCapital} \times (\text{ratio} / 100)}{\text{price} \times 100} \right\rfloor \times 100$$
- 扣除单边交易手续费。
- 留存未满一手的剩余现金。

### 1.3 价格记忆维护与停牌处理

- 若标的在当日停牌、处于非交易日或未上市，价格自动沿用**历史最近一次有效的收盘价记忆** `lastValidPrices[code]`。
- 绝不归零，杜绝数据断裂与未来穿越。

### 1.4 延迟补仓机制

- 若某标的在回测首日尚无价格(即未上市)，系统不进行任何扣款，初始化份额为 0。
- 当时间轴推进到其上市首日(有了有效收盘价)时，系统自动触发**延迟建仓**，以当日总资产价值乘以该标的初始比例，折算买入份额。

## 2. 核心量化指标物理公式

文档与后端公共助手函数库 [helpers.js](file:///d:/trae/etf/server/src/utils/helpers.js) 及 [backtest.js](file:///d:/trae/etf/server/src/services/backtest.js) 的真实执行代码保持 **100% 绝对一致**：

### 2.1 年化收益率 (calcAnnualReturn)

几何年化收益率计算：
$$\text{AnnualReturn} = \left( \left( 1 + \frac{\text{TotalReturn}}{100} \right)^{\frac{1}{\text{Years}}} - 1 \right) \times 100\%$$
- 代码实现：
  ```javascript
  function calcAnnualReturn(totalReturn, years) {
    if (years <= 0 || totalReturn <= -100) return 0;
    return (Math.pow(1 + totalReturn / 100, 1 / years) - 1) * 100;
  }
  ```

### 2.2 最大回撤度 (calcMaxDrawdown)

根据每日资产净值数组逐日追踪历史最高净值并记录最大下跌比例：
- 代码实现：
  ```javascript
  function calcMaxDrawdown(values) {
    if (!values || values.length < 2) return 0;
    let maxValue = values[0];
    let maxDrawdown = 0;
    for (let i = 1; i < values.length; i++) {
      if (values[i] > maxValue) {
        maxValue = values[i];
      }
      const drawdown = (maxValue - values[i]) / maxValue * 100;
      if (drawdown > maxDrawdown) {
        maxDrawdown = drawdown;
      }
    }
    return maxDrawdown;
  }
  ```

### 2.3 年化波动率 (calcVolatility)

由每日收益率计算样本方差并乘以 252 交易日开根号：
$$\text{Volatility} = \sqrt{\text{Variance(dailyReturns)} \times 252}$$
- 代码实现：
  ```javascript
  function calcVolatility(dailyReturns) {
    if (!dailyReturns || dailyReturns.length < 2) return 0;
    const mean = dailyReturns.reduce((a, b) => a + b, 0) / dailyReturns.length;
    const variance = dailyReturns.reduce((a, b) => a + Math.pow(b - mean, 2), 0) / (dailyReturns.length - 1);
    return Math.sqrt(variance * 252);
  }
  ```

### 2.4 夏普比率 (calcSharpeRatio)

采用行业标准的超额收益风险调整公式，系统回测底层默认无风险收益率为 **2.5%**：
- 代码实现：
  ```javascript
  function calcSharpeRatio(annualReturn, riskFreeRate = 2.5, annualVolatility) {
    if (annualVolatility <= 0) return 0;
    return (annualReturn - riskFreeRate) / annualVolatility;
  }
  ```

### 2.5 当前回撤比例 (calcCurrentDrawdown)

- 代码实现：
  ```javascript
  function calcCurrentDrawdown(currentValue, historyHighValue) {
    if (historyHighValue <= 0) return 0;
    return (historyHighValue - currentValue) / historyHighValue * 100;
  }
  ```

### 2.6 其他辅助工具函数 (helpers.js 全量导出)

| 函数名 | 说明 |
| --- | --- |
| `calcRallyPercent(currentValue, lowValue)` | 计算从最低点反弹幅度百分比: `(current - low) / low * 100` |
| `calcAnnualReturnFromDates(totalReturn, startDate, endDate)` | 自动由日期字符串计算年数，再调用 `calcAnnualReturn` |

## 3. 初始比例启用/禁用与专属步长联动（乘数模型）

### 3.1 资产一键启用/禁用与物理清洗
- **启用开关**：在初始配置中如果勾选禁用（`isEnabled: false`），占比强制重置为 `0`，且在策略配置中完全隐形这一列。
- **回测洗净**：后端 `runBacktest` 启动第一时间，自动加载 `Stock.findAll("is_enabled = 0")` 的资产代码，并从回测标的 `etfs` 数组与初始配比 `initialRatios` 中进行**物理过滤剥离删除**，阻断一切未来脏交易。

### 3.2 专属步长联动公式
策略配置中各档位不保存绝对占比，而是保存倍数（`targetRatio`，整数）。
实际占比在回测中通过乘积公式动态计算：
$$\text{目标持仓比}_i = \text{初始持仓比}_i + \text{倍数}_i \times \text{专属步长}_i$$

## 4. 策略 A: 净值高低点回撤分档策略

### 4.1 策略定位

**锚定基准**: 组合的历史累计最高净值（新高）  
**核心逻辑**: 下跌分档加仓、反弹跨级退档、新高一键复位。

### 4.2 函数签名与执行逻辑（忠实于代码）

代码实现于 `backtest.js` 中的 `evaluateStrategyA` 方法：

```javascript
function evaluateStrategyA(config, drawdown, historyHigh, currentValue, currentALevel, initialRatios, stepRatios = {}) {
    // 1. 创新高复位逻辑 (最高优先级)
    if (config.resetOnHigh && currentValue >= historyHigh && historyHigh > 0) {
        if (currentALevel !== 0) {
            return {
                action: 'reset',
                reason: '组合净值创历史新高，自动复位至初始配置比例',
                ratios: { ...initialRatios },
                newLevel: 0,
                resetHigh: true
            };
        }
        return null;
    }

    // 2. 按回撤幅度寻找当前满足的最高回撤档位（回撤幅度按 threshold 从大到小排序）
    const sortedLevels = (config.drawdownLevels || []).sort((a, b) => b.threshold - a.threshold);
    let expectedLevel = 0;
    let expectedRatios = null;

    for (const level of sortedLevels) {
        if (drawdown >= level.threshold) {
            expectedLevel = level.levelOrder;
            const ratios = {};
            (level.ratios || []).forEach(r => { 
                const step = stepRatios[r.etfCode] || 5.0;
                ratios[r.etfCode] = (initialRatios[r.etfCode] || 0) + (r.targetRatio * step); 
            });
            expectedRatios = ratios;
            break;
        }
    }

    // 3. 档位加深判定（下跌加仓）
    if (expectedLevel > currentALevel) {
        return {
            action: 'drawdown',
            reason: `回撤深达 ${drawdown.toFixed(2)}%，触发第 ${expectedLevel} 档加仓配置`,
            ratios: expectedRatios,
            newLevel: expectedLevel,
            resetHigh: false
        };
    }

    // 4. 反弹跨级退档判定（多跨一档才开始调仓，非零不回归初始）
    if (currentALevel > 0 && drawdown > 0) {
        const shallowerLevelOrder = currentALevel - 1;
        if (shallowerLevelOrder > 0) {
            // 获取更浅一档的加仓阈值
            const targetLevelConfig = (config.drawdownLevels || []).find(l => l.levelOrder === shallowerLevelOrder);
            if (targetLevelConfig && drawdown < targetLevelConfig.threshold) {
                const ratios = {};
                (targetLevelConfig.ratios || []).forEach(r => { 
                    const step = stepRatios[r.etfCode] || 5.0;
                    ratios[r.etfCode] = (initialRatios[r.etfCode] || 0) + (r.targetRatio * step); 
                });
                return {
                    action: 'rebound',
                    reason: `回撤收窄至 ${drawdown.toFixed(2)}%（涨至第 ${shallowerLevelOrder} 档阈值以内），下调成 ${shallowerLevelOrder} 档配置`,
                    ratios,
                    newLevel: shallowerLevelOrder,
                    resetHigh: false
                };
            }
        }
    }

    return null; // 属于反弹不够或中间震荡，坚守当前档位不调仓
}
```

## 5. 策略 B: 长期年化收益率偏离估值策略

### 5.1 策略定位

**锚定基准**: 设定的组合长期年化中枢收益率  
**核心逻辑**: 实际运行时间几何累计年化偏离中枢时高估减仓、低估加仓。

### 5.2 运行时间与实际年化计算（忠实于代码）

系统回测主循环时通过精确计算日期毫秒数得出流逝年数：
```javascript
const yearsCount = (new Date(date) - new Date(startDate)) / (365 * 24 * 60 * 60 * 1000);
const currentAnnualReturn = calcAnnualReturn(totalReturn, Math.max(yearsCount, 0.1));
const deviation = currentAnnualReturn - config.centralAnnual;
```

### 5.3 函数签名与执行逻辑（忠实于代码）

代码实现于 `backtest.js` 中的 `evaluateStrategyB` 方法：

```javascript
function evaluateStrategyB(config, deviation, currentLevel, initialRatios, stepRatios = {}) {
    let expectedLevel = 0;
    let expectedRatios = { ...initialRatios };
    let reason = '估值偏离回归正常范围，自动复位至初始配置比例';
    let action = 'reset';

    // 查找当前偏差满足的最高高估档位
    const sortedOvervalued = (config.overvaluedLevels || []).sort((a, b) => b.levelOrder - a.levelOrder);
    for (const level of sortedOvervalued) {
        if (deviation >= level.threshold) {
            expectedLevel = level.levelOrder;
            expectedRatios = {};
            (level.ratios || []).forEach(r => { 
                const step = stepRatios[r.etfCode] || 5.0;
                expectedRatios[r.etfCode] = (initialRatios[r.etfCode] || 0) + (r.targetRatio * step); 
            });
            reason = `年化偏离度为 ${deviation.toFixed(2)}%，达到高估档位 ${level.levelOrder} (${level.threshold}%)`;
            action = 'overvalued';
            break;
        }
    }

    // 如果没有满足的高估档位，查找满足的最高低估档位
    if (expectedLevel === 0) {
        const sortedUndervalued = (config.undervaluedLevels || []).sort((a, b) => b.levelOrder - a.levelOrder);
        for (const level of sortedUndervalued) {
            if (deviation <= -level.threshold) {
                expectedLevel = -level.levelOrder;
                expectedRatios = {};
                (level.ratios || []).forEach(r => { 
                    const step = stepRatios[r.etfCode] || 5.0;
                    expectedRatios[r.etfCode] = (initialRatios[r.etfCode] || 0) + (r.targetRatio * step); 
                });
                reason = `年化偏离度为 ${deviation.toFixed(2)}%，达到低估档位 ${level.levelOrder} (-${level.threshold}%)`;
                action = 'undervalued';
                break;
            }
        }
    }

    // 只有在档位级别真正发生变化时，才触发调仓交易
    if (expectedLevel !== currentLevel) {
        return {
            action,
            reason,
            ratios: expectedRatios,
            newLevel: expectedLevel
        };
    }

    return null;
}
```

## 9. 交易费用计算 (calcFee)

精确对接真实代码费率模型，含有百分比到小数折算及免五自适应：
- 代码实现：
  ```javascript
  function calcFee(amount, rate, exemptFive) {
    // 交易费率：金额 * 费率(%) / 100
    let fee = amount * (rate / 100);
    // 最低单笔5元限制
    if (!exemptFive && fee < 5) {
      fee = 5;
    }
    // 四舍五入到 2 位小数（分）
    return Math.round(fee * 100) / 100;
  }
  ```

## 10. 偏离加权和守恒定律 (配平规则)

前端在进行策略 A、策略 B 各档位微调倍数保存时，每一档已启用的标的代码其 `倍数 * 步长` 的总偏离之和必须为 **0%**。
即高配和降配在数学逻辑上严格对称，由此保障任何一档在叠加了专属步长乘数后，总实际持仓恒等于 100%。

## 11. 边界条件特殊处理规范

| 场景 | 引擎物理处理方式 |
| --- | --- |
| **首日建仓买入** | 按 `Math.floor(targetValue / price / 100) * 100` 向下取整到手交易 |
| **买入现金受限** | 折算最大可买入份数 `Math.floor((remainingCash * 0.999) / price / 100) * 100`，预留千分之一做手续费缓冲 |
| **卖出降配操作** | 按 `Math.ceil(diffValue / price / 100) * 100` 向上取整，限制超卖与超买，防止透支 |
| **停牌接管** | 当日停牌标的使用最近有效价格记忆 `lastValidPrices[code]`，绝不归零 |
| **延迟建仓** | 首日未上市标的份额初始化为 0，上市首日有效价格出现时自动触发延迟建仓 |
| **每日价值更新** | 先执行延迟建仓，再计算当日总市值：`totalValue = cash + 所有标的 shares × price 累加和` |

## 12. 交易执行引擎 (executeTrades)

```javascript
function executeTrades(portfolio, prices, targetRatios, totalValue, cash, feeRate, feeExemptFive, reason, tradeType)
```

**执行顺序**：

1. **计算待交易展望** —— 对每个已有价格的标的计算走差 `sharesDelta`：
   - 买入（`diffValue >= 0`）: `Math.floor(diffValue / price / 100) * 100` 向下取整 → 防止超支
   - 卖出（`diffValue < 0`）: `Math.ceil(diffValue / price / 100) * 100` 向零取整 → 防止超卖
2. **先执行所有卖出** —— 捕获现金，避免买入时现金不足
3. **后执行所有买入** —— 环使用卖出回笼的现金；如现金仍不足，则按 `remainingCash * 0.999` 限额买入
4. **返回更新后的** `{ portfolio, cash, marketValue, trades }`

**交易单笔最小单位**: 100 股（1手）的整倍数，不足 1 手的差额不交易。
