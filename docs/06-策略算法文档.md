## 1. 回测引擎核心流程

回测引擎位于 `server/src/services/backtest.js`，采用"时间流动轴"沙盒模型，在内存中闭环运行，逐日推进。

### 1.1 总体流程

```
启动回测参数 -> 锁定基准(510300)
  -> 读取所有标的历史行情
  -> 回测首日: 自动建仓(100股向下取整)
  -> 逐日时间轴主循环:
     -> 更新每日行情与价格记忆
     -> 延迟补仓(针对首日未上市标的)
     -> 策略A信号研判
     -> 策略B信号研判
     -> 决策融合引擎(按优先级合并)
     -> 日常再平衡偏离度校验
     -> 推进到下一交易日
  -> 循环结束
  -> 计算全套量化指标
  -> 存盘输出
```

### 1.2 首日建仓规则

- 读取各标的在回测首日的收盘价
- 依据配置的 `initialRatios` 占比进行初始配资
- 买入股数按 **100 股(一手)向下取整**
- 扣除交易手续费(内置最低单笔5元限制)
- 留存剩余现金(未被分配

```javascript
const maxShares = Math.floor(capitalAllocated / (price * 100)) * 100
```

### 1.3 价格记忆维护

- 若标的在当日停牌或无交易，价格自动沿用最近有效收盘价
- 绝不归零或使用默认值

### 1.4 延迟补仓机制

- 若标的首日尚无收盘价(未上市)，则保留现金等待
- 时间轴推进到其有有效收盘价的首日时，自动触发延迟建仓
- 按初始占比补足仓位

### 1.5 量化指标计算

回测结束后计算以下指标：

| 指标 | 计算公式 | 说明 |
| --- | --- | --- |
| 总收益率 | (最终市值 - 初始资金) / 初始资金 * 100% | 累计收益百分比 |
| 年化收益率 | (1 + 总收益率) ^ (250 / 总交易日数) - 1 | 按 250 交易日年化 |
| 最大回撤 | min(当日市值 / 历史最高市值 - 1) | 历史最大亏损幅度 |
| 年化波动率 | std(日收益率) * sqrt(250) | 风险度量 |
| 夏普比率 | (年化收益率 - 无风险利率) / 年化波动率 | 风险调整后收益 |

## 2. 策略 A: 净值高低点回撤/反弹档位策略

### 2.1 策略定位

**类型**: 右侧进攻型策略  
**锚定基准**: 资产组合的历史累计最高市值(新高)  
**核心逻辑**: 市场深幅回撤时加仓，从阶段低点反弹时减仓

### 2.2 创新高复位

- 当日组合市值创历史新高时
- 清空所有策略加减仓级别
- 目标占比重置为初始比例

```javascript
if (totalValue > historicalHigh) {
  historicalHigh = totalValue
  currentLevel = 0
  rallyLevel = 0
  targetRatios = { ...initialRatios }
}
```

### 2.3 回撤加仓逻辑

从历史最高点计算当前回撤幅度：

```
drawdownPercent = (historicalHigh - totalValue) / historicalHigh * 100
```

- 当 `drawdownPercent` 达到第 N 档阈值时，触发加仓
- 加仓提升高弹性资产(如股票类 ETF)的占比
- 降配低弹性资产(如债券、黄金)的占比
- 每个档位对应一组预设的 ETF 目标比例

### 2.4 反弹减仓逻辑

从阶段低点计算反弹幅度：

```
rallyPercent = (totalValue - stageLow) / stageLow * 100
```

- 当系统处于加仓级别(level > 0)时启动反弹监测
- self.rally的反弹幅度达到阈值时触发有序逐级减仓
- 反弹幅度低于 1.0% 时自动复位 rallyLevel(防止小幅波动误判)

```javascript
if (rallyPercent < 1.0) {
  self.rallyLevel = 0
}
```

### 2.5 防超买超卖安全防护

减仓执行前校验目标占比：

- 若计算出的目标股票占比反而比当前实际持仓更高
- 视为"反向误操作"，静默拒绝执行

## 3. 策略 B: 长期年化收益率偏离估值策略

### 3.1 策略定位

**类型**: 均值回归型策略  
**锚定基准**: 设定的组合长期年化中枢收益率  
**核心逻辑**: 实际年化偏离中枢时高估减仓、低估加仓

### 3.2 年化收益率计算

采用回测区间的实际年化收益率：

```javascript
const totalReturn = totalValue / initialCapital
const years = totalDays / 250
const actualAnnualReturn = Math.pow(totalReturn, 1 / years) - 1
```

### 3.3 高估防御档位

- 当 `actualAnnualReturn - targetAnnualReturn >= threshold[N]`
- 说明市场过热
- 触发高估防御，降低风险资产(股票类)占比
- 提高债券/现金类资产占比

### 3.4 低估进攻档位

- 当 `targetAnnualReturn - actualAnnualReturn >= threshold[N]`
- 说明市场过冷
- 触发低估进攻，提高风险资产占比
- 在底部收集筹码

## 4. 决策融合引擎

### 4.1 问题背景

双策略在同一交易日可能同时触发调仓信号，若分别执行会造成：

- 先按策略A调仓，再按策略B调仓，产生双重摩擦
- 买卖方向冲突时相互擦除
- 重复扣取手续费

### 4.2 融合规则

```javascript
let chosenResult = null
if (aResult && bResult) {
  // 按优先级: 用户预设 strategyPriority
  chosenResult = strategyPriority === 'strategy_b' ? bResult : aResult
} else {
  chosenResult = aResult || bResult
}
// 执行一次性调仓
if (chosenResult) {
  executeRebalance(chosenResult.targetRatios)
}
```

### 4.3 优先级配置

- 用户可在策略配置页设置双策略优先级：

- `strategy_a`: 策略A优先(默认)
- `strategy_b`: 策略B优先

## 5. 日常再平衡机制

### 5.1 触发条件

每个非策略信号交易日，逐日校验：

```
singleDeviation = |actualRatio - targetRatio|
```

- 任意单标的偏离度绝对值 > `rebalanceThreshold`(如 1.5%)
- 触发日常再平衡

### 5.2 执行逻辑

- 一次性对齐所有标的占比到当前档位目标比例
- 不改变当前激活的策略档位
- 仅恢复目标占比分布

## 6. 参数寻优

### 6.1 寻优范围

系统自动遍历 `rebalanceThreshold` 参数：

- 范围: 0.8% 到 5.0%
- 步长: 0.5%

### 6.2 防爆盘保护

```javascript
const isOptimization = params.rebalanceThreshold !== undefined
```

- 寻优模式下 `dailyDetail` 字段写入空字符串
- 避免海量 JSON 数据撑爆数据库

### 6.3 排序输出

按年化收益率降序排列，方便用户选出最优方案。

## 7. 交易费用模型

### 7.1 费率配置

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| feeRate | 0.0003 (0.03%) | 单边交易佣金费率 |
| minFee | 5 元 | 单笔最低佣金 |
| feeExemptFive | true | 是否免除最低5元限制 |

### 7.2 计算方式

```
fee = max(amount * feeRate, feeExemptFive ? 0 : minFee)
```

### 7.3 交易限价

- 买入: 以当日收盘价 * 1.005 作为最高限价
- 卖出: 以当日收盘价 * 0.995 作为最低限价

## 8. 参数约束规则

### 8.1 全局参数约束

| 参数 | 最小值 | 最大值 | 说明 |
| --- | --- | --- | --- |
| annualReturnTarget | 1.0 | 20.0 | 年化目标收益率(%) |
| rebalanceThreshold | 0.5 | 10.0 | 再平衡阈值(%) |
| feeRate | 0.0001 | 0.0100 | 交易费率 |
| initialRatio | - | 100.0 | 初始占比，各 ETF 之和须为 100% |

### 8.2 策略 A 参数约束

| 参数 | 最小值 | 最大值 | 说明 |
| --- | --- | --- | --- |
| drawdown 阈值 | 1.0 | 50.0 | 回撤触发阈值(%)，按 level 递增 |
| rally 阈值 | 1.0 | 50.0 | 反弹触发阈值(%)，按 level 递增 |
| ratios 各 ETF 占比 | - | 100.0 | 各档位目标占比之和须为 100% |

### 8.3 策略 B 参数约束

| 参数 | 最小值 | 最大值 | 说明 |
| --- | --- | --- | --- |
| overvalued 阈值 | 0.5 | 20.0 | 高估触发阈值(%)，按 level 递增 |
| undervalued 阈值 | 0.5 | 20.0 | 低估触发阈值(%)，按 level 递增 |

### 8.4 配置校验规则

- 各 ETF 初始占比之和必须等于 100%(允许 ±0.01 浮点误差)
- 策略 A/B 各档位目标占比之和必须等于 100%
- 策略档位 level 从 1 开始，依次递增，不可跳级
- 阈值大小必须与 level 正相关(level 越高，阈值越大)

## 9. 边界条件处理规范

### 9.1 数据边界

| 场景 | 处理方式 |
| --- | --- |
| 历史数据不足 | 回测至少需要 20 个交易日数据，不足时拒绝执行 |
| 停牌/无数据日 | 自动沿用最近有效收盘价，不归零，不报错 |
| 首日未上市标的 | 保留现金等待，有数据后触发延迟补仓 |
| 价格异常(0 或负数) | 跳过当日，沿用前一交易日价格 |

### 9.2 资金边界

| 场景 | 处理方式 |
| --- | --- |
| 现金不足买入 | 跳过买入操作，记录日志 |
| 持仓不足卖出 | 跳过卖出操作，记录日志 |
| 手续费超过交易金额 | 仍收取全额手续费(不超过交易金额) |
| 剩余零股(< 100 股) | 保留在账户中，不强制卖出 |

### 9.3 策略边界

| 场景 | 处理方式 |
| --- | --- |
| 多策略同日触发 | 按优先级规则融合为一次调仓 |
| 目标占比计算后 > 100% | 归一化处理，确保总和为 100% |
| 反弹幅度 < 1.0% | 自动复位 rallyLevel，防止小幅波动误判 |
| 减仓时目标占比反而高于当前 | 视为反向误操作，静默拒绝 |
| 创新高时清空所有策略级别 | 目标占比重置为初始比例 |

### 9.4 配置边界

| 场景 | 处理方式 |
| --- | --- |
| 参数超出约束范围 | 前端校验拦截，后端再次校验 |
| 数据库写入失败 | 回滚事务，返回错误提示 |
| 寻优参数不存在 | 使用默认值(0.8%~5.0%，步长 0.5%) |
