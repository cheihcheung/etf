## 1. 技术栈说明

本项目后端采用 **Node.js + Express + MySQL** 架构，遵循 MVC 分层设计。

**说明**:

- Node.js 是项目的后端运行环境
- Express 4.x 作为 Web 框架
- 采用极简 ORM 基类封装数据库操作
- 核心算法在服务层内存沙盒中闭环运行

## 4. 数据模型层 (Models)

### 4.1 BaseModel 基类

所有模型继承自 `BaseModel.js`，提供通用的 ORM 操作方法：

| 方法 | 说明 | 示例 |
| --- | --- | --- |
| `find(id)` | 按主键查询 | `Stock.find(1)` |
| `findOne(conditions)` | 按条件查单条 | `Stock.findOne({ code: '510300' })` |
| `findAll(where, params, order, limit)` | 按条件查列表 | `Stock.findAll('asset_type = ?', ['股票'], 'code ASC')` |
| `create(data)` | 创建记录 | `Stock.create({ code: '510300' })` |
| `update(id, data)` | 按主键更新 | `Stock.update(1, { name: '新名称' })` |
| `updateWhere(conditions, params, data)` | 条件更新 | `Stock.updateWhere({ code: '513100' }, [], { name: '纳指ETF' })` |
| `delete(id)` | 按主键删除 | `Stock.delete(1)` |
| `deleteWhere(conditions, params)` | 条件删除 | `Stock.deleteWhere({ code: '513100' })` |

### 4.2 模型定义示例

```javascript
const BaseModel = require('./BaseModel');

class Stock extends BaseModel {
    static get tableName() {
        return 'stock';
    }
}

module.exports = Stock;
```

### 4.4 事务支持

BaseModel 提供事务支持，用于配置批量更新等需要原子性的操作：

```javascript
const db = require('../config/db');

// 使用事务包裹
await db.transaction(async () => {
  await StrategyAConfig.deleteWhere('1 = 1');
  for (const level of levels) {
    await StrategyAConfig.create(level);
  }
  await GlobalConfig.update(existing.id, { config_value: 'true' });
});
```

### 4.5 查询示例

```javascript
const Stock = require('../models/Stock');

// 获取单条
const etf = await Stock.findOne({ code: '510300' });

// 获取列表(参数绑定防注入)
const stockEtfs = await Stock.findAll(
  'asset_type = ? AND initial_ratio > ?',
  ['股票', 10]
);

// 创建记录
await Stock.create({
  code: '513100',
  name: '纳指ETF',
  asset_type: '股票',
});

// 条件更新
await Stock.updateWhere({ code: '513100' }, [], {
  name: '纳斯达克100ETF',
  initial_ratio: 15.0000,
});
```

## 5. 路由控制层 (Routes)

### 5.1 路由命名规范

| 操作 | HTTP 方法 | URL 格式 | 说明 |
| --- | --- | --- | --- |
| 列表查询 | GET | `/etf/list` | 获取列表数据 |
| 获取单条 | GET | `/etf/detail/:code` | 按标识获取详情 |
| 创建 | POST | `/etf/create` | 新建资源 |
| 更新 | PUT | `/etf/update` | 全量更新 |
| 删除 | DELETE | `/etf/delete/:code` | 删除资源 |
| 执行操作 | POST | `/backtest/run` | 触发业务操作 |
| 批量同步 | POST | `/etf/sync-all` | 批量操作 |

**命名约定**:

- 路径使用 kebab-case 小写
- 避免在 URL 中包含动词（除标准 CRUD 外），如用 `/backtest/run` 而非 `/backtest/executeBacktest`
- 资源标识放在 URL 参数中，如 `/etf/delete/:code`
- 复杂查询参数放在 query string 中

### 5.2 标准路由结构

```javascript
const express = require('express');
const router = express.Router();
const logger = require('../utils/logger');
const Stock = require('../models/Stock');

// GET - 列表查询
router.get('/list', async (req, res) => {
  try {
    const data = await Stock.findAll();
    res.json({ success: true, data });
  } catch (error) {
    logger.error(`查询ETF列表失败: ${error.message}`);
    res.status(500).json({ success: false, message: error.message });
  }
});

// POST - 创建
router.post('/create', async (req, res) => {
  try {
    const { code, name, assetType } = req.body;
    // 参数校验
    if (!code || !name || !assetType) {
      return res.status(400).json({ success: false, message: '请填写完整信息' });
    }
    await Stock.create({ code, name, asset_type: assetType });
    logger.info(`创建ETF: ${code}`);
    res.json({ success: true, message: '创建成功' });
  } catch (error) {
    logger.error(`创建ETF失败: ${error.message}`);
    res.status(500).json({ success: false, message: error.message });
  }
});

// PUT - 更新
router.put('/update', async (req, res) => {
  try {
    const { code, name } = req.body;
    if (!code) {
      return res.status(400).json({ success: false, message: '缺少code参数' });
    }
    await Stock.updateWhere({ code }, [], { name });
    res.json({ success: true, message: '更新成功' });
  } catch (error) {
    logger.error(`更新ETF失败: ${error.message}`);
    res.status(500).json({ success: false, message: error.message });
  }
});

// DELETE - 删除
router.delete('/delete/:code', async (req, res) => {
  try {
    const { code } = req.params;
    await Stock.deleteWhere({ code });
    logger.info(`删除ETF: ${code}`);
    res.json({ success: true, message: '删除成功' });
  } catch (error) {
    res.status(500).json({ success: false, message: error.message });
  }
});

module.exports = router;
```

### 5.3 路由层职责

| 职责 | 说明 |
| --- | --- |
| HTTP 请求分发 | 匹配 URL 和方法 |
| 参数校验 | 检查必填参数、参数格式 |
| 响应输出 | 统一 JSON 格式返回 |
| 错误日志 | 关键操作记录日志 |
| 状态码管理 | 200 成功、400 参数错误、404 不存在、500 服务器错误 |

### 5.4 统一响应格式

**成功响应**:

```json
{
  "success": true,
  "data": {},
  "message": "操作成功"
}
```

**错误响应**:

```json
{
  "success": false,
  "message": "错误描述信息"
}
```

**参数校验失败**:

```json
{
  "success": false,
  "message": "请填写完整的ETF信息"
}
```

### 5.5 HTTP 状态码使用

| 状态码 | 使用场景 |
| --- | --- |
| 200 | 请求成功，正常返回数据 |
| 400 | 参数缺失或格式错误 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误（统一在 catch 中返回） |

## 6. 服务层 (Services)

### 6.1 回测引擎 (backtest.js)

核心业务流程：

1. 参数对齐与动态基准加载
2. 读取历史行情数据
3. 首日初始建仓(100股向下取整)
4. 逐日时间轴推进：
   - 更新每日行情与价格记忆
   - 延迟补仓(上市首日建仓)
   - 策略 A/B 信号并行研判
   - 决策融合引擎(优先级合并)
   - 日常再平衡偏离度校验
5. 计算全套量化指标
6. 存盘输出

### 6.2 策略引擎 (strategyA.js / strategyB.js)

- 策略 A: 净值高低点回撤/反弹档位策略
- 策略 B: 长期年化中枢偏离估值策略
- 决策融合: 双策略冲突时按优先级合并

### 6.3 行情爬虫 (spider.js)

- 数据源: 腾讯/东方财富 API (且支持物理导入同花顺等导出行情)
- 功能: 实时行情、历史日 K 线
- 容错: 网络异常时自动重试、数据缺失时沿用最近价格

### 7.3 CORS 中间件与 Express 配置

```javascript
// server/src/index.js
const express = require('express');
const cors = require('cors');
const logger = require('./utils/logger');

const app = express();

// CORS 配置（允许前端跨域访问）
app.use(cors({
  origin: ['http://localhost:8088', 'http://localhost:5173'],
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
}));

app.use(express.json());

// 路由挂载
app.use('/api/etf', require('./routes/etf'));
app.use('/api/config', require('./routes/config'));
app.use('/api/backtest', require('./routes/backtest'));
app.use('/api/records', require('./routes/records'));

// 全局错误处理中间件
app.use((err, req, res, next) => {
  logger.error(`未捕获异常: ${err.message}`);
  res.status(500).json({ success: false, message: '服务器内部错误' });
});

const PORT = process.env.SERVER_PORT || 3001;
app.listen(PORT, () => {
  logger.info(`服务已启动，端口: ${PORT}`);
});
```

## 8. 编码规范

### 8.1 通用规则

- 使用 `async/await` 处理异步操作，禁止使用回调
- 所有数据库查询通过模型层完成，禁止裸写 SQL
- 参数绑定防止 SQL 注入，禁止字符串拼接 SQL
- 日志使用 `utils/logger.js` 统一记录
- 模块间通过 require 引入，保持单向依赖（路由 → 服务 → 模型）

### 8.2 路由层规范

- 路由方法统一使用 `async (req, res) => { ... }` 形式
- 所有路由方法使用 try-catch 包裹异常
- 成功响应使用 `res.json({ success: true, data })`
- 参数校验失败使用 `res.status(400).json({ success: false, message })`
- 服务器错误统一在 catch 中通过 `res.status(500).json({ success: false, message })` 返回
- 关键操作（创建、删除、配置变更）记录操作日志

### 8.3 模型层规范

- 所有模型继承 BaseModel，只需定义 `tableName` 静态属性
- 查询条件使用参数绑定语法（`?` 占位符）
- 批量更新操作使用事务保证一致性
- 不定义不必要的模型方法，优先使用 BaseModel 通用方法

### 8.4 服务层规范

- 核心算法在内存沙盒中闭环运行，不依赖数据库事务
- 回测引擎逐日推进，确保无未来数据穿越
- 参数寻优时设置 `isOptimization: true` 防止数据库爆盘
- 交易股数严格 100 股取整
- 服务层不直接处理 HTTP 请求和响应

### 8.5 安全规范

- 所有用户输入通过参数绑定防注入
- 不暴露数据库结构信息和内部错误详情
- 敏感配置（数据库密码等）通过环境变量管理
- 删除操作前进行前置条件校验（如删除 ETF 前检查占比）
